# ethang.dev

A fully static site, generated by a Rust binary and deployed to Cloudflare with the
`cf` CLI. The build reads `content/` and writes plain HTML, CSS, and assets to `dist/`.

## Constraints

- **No JavaScript or TypeScript, anywhere.** Not in the source tree, not in the build
  output. The site is HTML, CSS, and assets only. `tests/no_javascript.rs` enforces this
  over both the repository and `dist/`, so a build step that reaches for a JS tool fails
  the test suite first.
- **`cargo` is the only package manager.** There is no `package.json`, no `node_modules`,
  no bundler, no Tailwind. Do not run `npm`, `npx`, `pnpm`, or `cf init` - `cf init`
  generates `cloudflare.config.ts` and `vite.config.ts`, which would break the rule above.
- **The output is a static site**, deployed as an assets-only worker. No Cloudflare Pages,
  no server-side rendering.

## Usage

```sh
cargo run -- build            # writes dist/
cargo run -- build --out tmp  # writes elsewhere
cargo test                    # includes the no-JavaScript guard
```

## Deploy

`wrangler.jsonc` is the deploy configuration: JSONC, not TypeScript. It declares the
`./dist` asset directory, `html_handling: "auto-trailing-slash"` (every route is emitted
as `<route>/index.html`, so a slash-free request such as `/blog/alpha` must resolve from
`blog/alpha/index.html`), `not_found_handling: "404-page"` (the generated `404.html`),
and the `ethang.dev` / `www.ethang.dev` custom domains. There is no `main` and no
`assets.binding`: nothing runs on the server, the assets are the whole deployment.

```sh
cargo run --release -- build --out dist
wrangler deploy                  # uploads the existing dist/
wrangler deploy --dry-run        # checks the config without uploading
```

`tests/deploy_config.rs` pins the parts of the config the build depends on, and fails if
a `cloudflare.config.ts`, `wrangler.config.ts`, or `vite.config.ts` reappears.

### Why `wrangler` and not `cf`

`cf deploy` reads a Build Output Specification tree (`.cloudflare/output/v0/`) rather
than `wrangler.jsonc`, and that format is still moving between betas: `cf` 1.0.0-beta.5
read the config file, while 1.0.0-beta.23 looks only for
`.cloudflare/output/v0/config.json` and fails with "no root config found" against this
repository. `wrangler` reads `wrangler.jsonc` directly, so the committed config stays the
single source of truth. Verified with `wrangler` 4.153.0.

Do not run `cf init` either: it scaffolds a TypeScript project (`cloudflare.config.ts`,
`vite.config.ts`, `src/index.ts`) and expects a Node manifest, which would break the
no-JavaScript rule above.

## Quality gates

The site is held to perfect Lighthouse scores and zero axe violations, checked
over every generated route rather than a sample.

```sh
python quality/audit.py                 # build, serve, audit all 46 routes
python quality/audit.py --skip-build    # audit the existing dist/
python quality/audit.py --only axe      # one tool
python quality/audit.py --routes /,/blog
```

The run fails unless every route scores 100 in performance, accessibility,
best-practices, and SEO, and reports no axe violation under the WCAG 2.0, 2.1,
and 2.2 AA tags. Reports land in `quality/reports/` (ignored by git).

A route whose only failures are marginal - 0.95 or above - is measured a second
time on its own before it is called a failure, because three headless browsers
sharing the machine move a timing audit by several percent: `total-blocking-time`
lands anywhere from 0ms to 131ms on the same unchanged page, which is enough to
take a route from 100 to 98. The retry is narrow on purpose - it needs *every*
failure on the route to be marginal, it runs once, and it runs with nothing else
competing. A real regression scores far below the line and fails on the first
reading. Each retry is printed, so a flake is visible rather than silently
absorbed, and `--no-retry` fails on the first reading instead.

```sh
python quality/test_audit.py            # the retry rule, without a browser
python quality/audit.py --no-retry      # fail on the first reading
```

`quality/serve.py` serves `dist/` the way Cloudflare does - trailing-slash
redirects, the generated 404, gzip, and long cache lifetimes on assets - because
auditing a bare file server measures things the deployed site never pays for.
It also points iframes at `about:blank`: a page with several third-party embeds
never settles, and axe waits on the load event until it times out.

Fonts are subsets. `assets/fonts/` holds the originals and
`static/fonts/` what ships; rerun the subsetter after changing copy, and
`tests/font_coverage.rs` fails if a character the site renders is not carried.

```sh
python quality/subset_fonts.py
```

## What the build emits

| Output | Purpose |
| --- | --- |
| `<route>/index.html` | One minified page per route, with its CSS inlined |
| `<route>/index.md` | The same page as markdown, for agents and for `llms.txt` |
| `llms.txt` | The [llms.txt](https://llmstxt.org/) index of those markdown files |
| `llms-full.txt` | The same document with every page body inlined |
| `blog/feed.xml` | The blog as RSS 2.0, newest first |
| `sitemap.xml`, `robots.txt`, `_redirects` | As before |

`static/styles/site.css` is a build input and is **not** published. Each page
carries a `<style>` element holding only the rules whose selectors can match that
page; `tests/css_pruning.rs` proves the pruned sheet matches exactly what the full
sheet matches, element for element, on every built page.

`tests/css_pruning.rs`, `tests/parity.rs`, and `tests/external_links.rs` all
read the committed `dist/`, so run `cargo run --release -- build` before
`cargo test` when any of them fails.

## Links

A link to another site opens in a new tab. `src/links.rs` rewrites every
anchor in the finished page whose `href` names a host other than `ethang.dev`,
adding `target="_blank"` and `rel="noopener noreferrer"`; a link within the
site, a `#fragment`, and a `mailto:` or `tel:` URL are left alone. The rewrite
runs once over the whole page rather than at each of the places an anchor is
built, because those places are in half a dozen modules and in markdown, and a
rule that has to be remembered in each of them is a rule that will be forgotten
in one. `tests/external_links.rs` checks every page the build writes, in both
directions: an external link that stays in the tab fails, and so does an
internal link that leaves it.

## Toolchain note

`rust-toolchain.toml` pins the GNU toolchain. This machine has no MSVC linker
(`link.exe`), so the default `x86_64-pc-windows-msvc` toolchain cannot link; the GNU
toolchain brings its own linker and needs no Visual Studio install.

## Layout

| Path | Purpose |
| --- | --- |
| `src/main.rs` | CLI: `build --out <dir>` |
| `src/lib.rs` | Module tree |
| `src/html.rs` | Escaping and the element builder |
| `src/links.rs` | External links open in a new tab |
| `src/content.rs` | Frontmatter, post loading, pagination |
| `src/markdown.rs` | Markdown plus the MDX component expander |
| `src/highlight.rs` | Build-time syntax highlighting |
| `src/math.rs` | LaTeX to MathML |
| `src/images.rs` | Build-time image resizing and srcsets |
| `src/css.rs` | CSS minification and per-page rule pruning |
| `src/llms.rs` | `llms.txt` and `llms-full.txt` |
| `src/rss.rs` | The blog's RSS 2.0 feed |
| `src/pages/` | One module per page |
| `static/` | Fonts, favicon, committed diagram SVGs |
| `content/` | Markdown posts and pages |
| `tests/` | Guard tests |
| `quality/` | Lighthouse and axe harness, font subsetter |
| `assets/fonts/` | Full font sources the subsets are cut from |
| `wrangler.jsonc` | Deploy configuration |
